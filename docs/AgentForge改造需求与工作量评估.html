01评估口径

  • 工作量单位：人天（pd），1 人天 = 1 名熟手工程师 1 个工作日

  • 性质：新建 从无到有 / 扩展 现有能力增强 / 薄封装 后端已有仅落 UI

07主要矛盾与风险提示

// 主要矛盾

本次改造的主要矛盾是「第 2 层后端新建能力」——占 46 人天、是所有 P0/P1 前端页面的数据地基。其中又以 2.1 Workflows 编排引擎（12 人天）为重中之重，它决定了 editor / debugger / workflows 三个核心页面能否成立。

// 三个必须先拍板的决策（否则范围会漂移）

  1. 视觉风格：沿用原型深色赛博风，还是对齐 deer-flow 现有风格？——影响全部 FE 工作量与需求 1.4。
  2. Workflows 引擎技术路线：基于 LangGraph 原生图扩展，还是引入独立工作流抽象层？——决定 2.1 的 12 人天是「扩展」还是「重写」。
  3. Datasets / Vector Stores 边界：是否与现有 thread uploads、memory 合并抽象？——避免重复造轮子。
