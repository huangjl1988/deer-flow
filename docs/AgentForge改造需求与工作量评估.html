01评估口径

  • 工作量单位：人天（pd），1 人天 = 1 名熟手工程师 1 个工作日

07主要矛盾与风险提示

// 主要矛盾

本次改造的主要矛盾是「第 2 层后端核心能力」——占 37 人天、是所有 P0/P1 前端页面的数据地基。其中又以 2.1 Workflows 编排引擎（8 人天，基于 LangGraph 原生图扩展）为重中之重，它决定了 editor / debugger / workflows 三个核心页面能否成立。

// 三项关键决策（已确认 · 2026-10-09）

  1. 视觉风格：已确认 — 沿用原型深色赛博风。统一 CSS 变量与组件 token，无需对齐 deer-flow 现有风格。需求 1.4 性质由"决策"转为落地实施。
  2. Workflows 引擎技术路线：已确认 — 基于 LangGraph 原生图扩展。复用 StateGraph / checkpoint / 执行内核，仅补 DAG 语义约束、版本化与可序列化定义。2.1 由"新建"降为"扩展"，BE 12→8 人天。
  3. Datasets / Vector Stores 边界：已确认 — 与现有 thread uploads、memory 合并抽象，避免重复造轮子。Datasets 复用 thread uploads 上传能力补元数据与版本；Vector Stores 复用 memory 后端向量抽象补多库管理。2.3 / 2.4 由"新建"降为"扩展"，BE 合计 14→9 人天。

决策影响汇总：三项决策确认后，第 2 层后端由 46→37 人天（-9），总工作量由原估 168→154 人天（决策 -11 + 明细修正 -3），关键路径工期由 3.5~4 个月缩短至 3~3.5 个月。
